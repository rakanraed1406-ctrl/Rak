# Jinxed Town — Military Logistics (qb-militaryhelipad-byrko 3.1)

متجر للقطاعات (CIA، LSPD، …): ميزانية لكل قطاع، سلة، طلب بتوصيل، **كراج أسطول** للمركبات، واستلام الأغراض بـ qb-target.

## الإيفنتات (اربطها بأي سكربت — interact / qb-target / ox_target)
| الوظيفة | الإيفنت (كلاينت) |
|---|---|
| فتح المتجر | `jt-logistics:open` |
| استلام الأسلحة والأغراض (عند الضابط) | `jt-logistics:supplies` |
| تخزين المركبات (عند الضابط) | `jt-logistics:store` |

**اسم الإيفنت لحاله يكفي**: يفتح أقرب متجر عندك صلاحية له. ولو عندك أكثر من متجر وتبي واحد معين، أرسل اسمه.
```lua
-- interact
options = { { label = 'Military Logistics', event = 'jt-logistics:open' } }
options = { { label = 'Military Logistics', event = 'jt-logistics:open', args = 'cia' } } -- متجر معين

-- qb-target / ox_target
{ type = 'client', event = 'jt-logistics:open', label = 'Military Logistics', shop = 'cia' } -- shop اختياري

-- من أي كود
TriggerEvent('jt-logistics:open')                    -- أقرب متجر
TriggerEvent('jt-logistics:open', 'cia')             -- متجر معين
TriggerClientEvent('jt-logistics:open', src, 'cia')  -- من السيرفر
exports['qb-militaryhelipad-byrko']:Open('cia')
exports['qb-militaryhelipad-byrko']:OpenSupplies('cia')
exports['qb-militaryhelipad-byrko']:OpenStore('cia')
```
مثال interact كامل:
```lua
exports.interact:AddInteraction({
    coords = vec3(-2035.03, 3116.78, 32.81), distance = 4.0, interactDst = 2.0, id = 'logistics_cia',
    options = { { label = 'Military Logistics', event = 'jt-logistics:open' } },
})
exports.interact:AddInteraction({
    coords = vec3(-2031.20, 3121.90, 32.81), distance = 4.0, interactDst = 2.0, id = 'logistics_cia_officer',
    options = {
        { label = 'Receive supplies', event = 'jt-logistics:supplies' },
        { label = 'Store the vehicle', event = 'jt-logistics:store' },
    },
})
```
السيرفر يتحقق من الصلاحية والمسافة كل مرة، فما يهم من وين ينفتح. (فيه بعد بوت `openPed` بـ qb-target لو تبيه.)

## التركيب
1. يحتاج: `qb-core`، `oxmysql`، `qb-target`، `qb-inventory`. (اختياري: `screenshot-basic` لتصوير المركبات.)
2. الجداول تنسوى لحالها أول تشغيل (`jt_logistics_shops / orders / depot`). `logistics.sql` لو تبيها يدوي.
3. عدّل `config.lua`: المتاجر، الصلاحيات، المنتجات، الأماكن. `/logisticscoords` (أدمن) يطبع لك `vector4` بالـ F8.

## كيف يمشي
1. **الفتح**: الشاشة تنفتح بالنص (مو كامل الشاشة) → شعار وزارة الداخلية → شريط تحميل 3 ثواني مع **JINXED TOWN** → الشعار ينتقل فوق يسار صغير → المتجر يطلع والكروت وحدة ورا الثانية.
2. **المتجر**: الميزانية فوق، شارة القطاع فوق يمين (CIA)، تبويبات (مدرعات، هليكوبترات، طائرات، أسلحة، أغراض)، وكل منتج له صورة وسعر وستوك.
3. **السلة**: تضيف أكثر من منتج وتعدل الكميات وتشوف الميزانية بعد الطلب → **PLACE ORDER**.
4. **التوصيل**: الطلب ياخذ `deliveryMinutes` (30 دقيقة). تشوف الطلبات اللي بالطريق مع عداد بزر **ORDERS**.
5. **الكراج (الأسطول)** — لما يوصل الطلب:
   - المركبة **تثبت بمكانها** (`display`) مثل الكراج: مركبة عرض وحدة لكل نوع، مقفلة ما تنركب، و**ما تختفي أبد** طول ما القطاع يملك منها شي (بالكراج أو طالعة).
   - **الإطلاع**: ناظرها بـ qb-target → **Garage — اسم المركبة** → تشوف `IN GARAGE` (كم موجود) و `OUT` (كم طالع) → تختار كم تطلع (طالب 3 ليزر؟ تطلع 1 أو 2 أو 3). كل وحدة تطلع بمكان فاضي من `spawnPoints` والمفاتيح والبنزين معك. لو كلها طالعة يكتب **ALL UNITS ARE OUT**.
   - **الإرجاع (التخزين)**: سوق المركبة لين **ضابط الإمداد** (`itemPed`) ووقفها جنبه (ضمن `storeRadius` = 30 متر) → ناظر الضابط بـ qb-target → **Store the vehicle** → تطلع لك قائمة بكل مركبات الأسطول الواقفة حوله (اللوحة، المسافة، حالة المحرك %) → تختار وحدة أو أكثر → **STORE** → ترجع للكراج وتقدر تطلعها مرة ثانية.
     - خيار **Store the vehicle** يطلع بس لما يكون فيه مركبات طالعة.
     - المدمرة (**WRECKED**) ما تنخزن. لو انفجرت وانشالت من الماب تروح من الأسطول (`Config.Fleet.DestroyedAreLost`).
     - ما تقدر تخزن مركبة غيرك سايقها، ولا أي مركبة مو من الأسطول.
     - لو المركبة انشالت من الماب لحالها (ما أحد قريب، ريستارت السيرفر) **ترجع للكراج تلقائي** — ما يضيع شي. (`Config.Fleet.KeepInWorld = true` لو تبيها تبقى مكانها.)
     - ريستارت للسكربت؟ المركبات الطالعة يتعرف عليها من جديد وتقدر تخزنها عادي.
   - **الأسلحة والأغراض**: من نفس الضابط → **Receive supplies** → تختار الكميات → تنضاف لشنطتك (لو ما تتسع يبقى الباقي بالمستودع).
6. **الميزانية**: `budget.daily` تنضاف كل 24 ساعة (مثلاً 500,000)، و **DEPOSIT** يخلي أي أحد معه صلاحية يودع من الكاش أو البنك.
7. **الستوك**: كل منتج له حد (`stock`) يترست كل 24 ساعة؛ لما يخلص يكتب **RESTOCK IN …**.

## الصلاحيات (لكل متجر)
```lua
access = { jobs = { cia = 0 }, gangs = {}, citizenids = { ['ABC123'] = true }, onDuty = false }, -- مين يفتح
permissions = {
    order = { jobs = { cia = 3 } }, -- الطلب من رتبة 3 وفوق (nil = نفس access)
    deposit = nil,                  -- الإيداع لكل اللي يفتحون
    pickup = nil,                   -- الاستلام لكل اللي يفتحون
},
terminal = { coords = vector3(...), distance = 15.0 }, -- اختياري: لازم يكون قريب عشان يطلب / يودع
```

## صور المركبات — كلها نفس الزاوية ونفس المكان ونفس الإضاءة
- **`/logisticsphotos`** (أدمن، يحتاج `screenshot-basic`): السكربت يصوّر كل مركبة بالمتجر **مرة وحدة**:
  تطلع المركبة في "استوديو" فوق البحر، الكاميرا تنحسب من **مقاس المركبة نفسها** (نفس الزاوية الأمامية الجانبية للكل، نفس البُعد بالنسبة لحجمها)، الوقت الظهر والجو صافي، خلفية ثابتة.
  تنأخذ صورتين (مع المركبة وبدونها)، والواجهة تقص المركبة **بدون خلفية** وتحطها بنص إطار 640×360 بنفس الهوامش → كل الصور متناسقة، حتى المركبات المضافة (addon).
  الصور تنحفظ في `html/img/vehicles/` (~10KB للصورة). بعدها سو **ريستارت للسكربت** عشان توصل للاعبين.
  `/logisticsphotos lazer` = مركبة وحدة.
- لو مركبة ما لها صورة: يستخدم صورة FiveM الرسمية للمركبات الأصلية (نفس الزاوية للكل)، وإذا ما فيه → أيقونة القسم.
- الأسلحة والأغراض: صورها من `qb-inventory` تلقائي.

## الأسطول بالكونفق
```lua
Config.Fleet = {
    DestroyedAreLost = true, -- المنفجرة تروح من الأسطول (false = ترجع للكراج)
    KeepInWorld = false,     -- true = الطالعة تبقى مكانها حتى لو ما أحد قريب
}
-- لكل متجر:
itemPed = { model = 's_m_y_marine_01', coords = vector4(...), label = 'Receive supplies', storeLabel = 'Store the vehicle' },
storeRadius = 30.0, -- المسافة من الضابط اللي تنقبل فيها المركبة
```

## أوامر الأدمن
- `/logisticsbalance cia 5000000` — تحدد ميزانية قطاع
- `/logisticsfleet cia lazer 3` — تحدد كم وحدة بالكراج (هدية / تعويض)
- `/logisticsrecall cia [lazer]` — يرجع كل مركبات الأسطول الطالعة (أو نوع واحد) للكراج
- `/logisticsphotos [model]` — تصوير المركبات
- `/logisticscoords` — يطبع إحداثياتك

## الاستهلاك
- **الكلاينت وقت ما تكون بعيد**: فحص مسافة وحد كل ثانيتين. مركبات العرض والمدنيين يطلعون بس لما تقرب (`DisplayDistance`).
- **الواجهة مقفلة** = `display:none`، ولا فيه أي مؤقت شغال. وهي مفتوحة: مؤقت واحد كل ثانية للعدادات.
- بدون مكتبات (لا jQuery ولا غيره)، الحركات كلها transform / opacity بس، بدون blur.
- **السيرفر**: كل شي بالذاكرة، فحص كل 30 ثانية للتوصيل والميزانية اليومية والأسطول (بس المركبات اللي طلعت من السكربت)، والتوصيل نفسه ينجدول على وقته بالضبط.
- **ضابط الإمداد**: ما فيه أي لوب — قائمة المركبات تنحسب بس لما تضغط Store.

## الحماية
- الأسعار، الستوك، الميزانية، الصلاحيات، والمسافات كلها من السيرفر. الكلاينت يرسل أرقام المنتجات والكميات بس.
- كل الأرقام لازم صحيحة موجبة (بدون سالب، كسور، NaN)، وفيه حد لكل طلب.
- قفل واحد لكل العمليات: طلبين بنفس اللحظة ما يقدرون يصرفون أكثر من الميزانية.
- المركبات يرسبنها السيرفر، والتخزين يقبل بس مركبات الأسطول اللي السيرفر نفسه طلعها (ما تقدر تخزن أي سيارة وتزيد الكراج)، وتكون فعلاً جنب الضابط، ومو مدمرة، وما أحد ثاني سايقها. كل مركبة تتخزن مرة وحدة بس.
- رفع الصور: أدمن بس + جلسة تصوير + اسم موديل من المتجر + لازم WEBP حقيقي.
- كل الأسماء بالواجهة نص عادي (اسم شخصية فيه كود ما يشتغل).

> ملاحظة: نظام الهنقر القديم (طيارات شخصية في `player_helicopters`) ما عاد مستخدم — صار كل شي للقطاعات.
